# Файлы из вашего ИИ

Подключите MCP по инструкции вашего приложения. Первое действие агента — `get_onboarding_state` с `intent: auto`. Дальше он использует текущую инструкцию сервера, сам выполняет разрешённые действия и спрашивает только недостающие данные. Можно продолжить тот же бизнес в вебе или Mini App.

Для тестового товара передайте полную карточку и отдельно полное сообщение цифровой доставки. Поддерживаются текст, сообщение только с медиа, фото, видео, PDF и другие допустимые документы, несколько файлов и допустимые альбомы. Фото не обязательно. Агент сохраняет подписи, форматирование и порядок файлов; подтверждает готовность и доставку серверными проверками.

Если приложение даёт краткоживущие HTTPS-ссылки на вложения, агент использует `media_import_files`. Путь к локальному файлу, base64 и выдуманная ссылка не подходят. Если приложение умеет читать байты и отправлять HTTP PUT, агент вызывает `media_request_upload`, загружает каждый файл по выданному URL с точным размером и завершает через `media_finalize`. Для восстановления есть `media_get_status`. Только подтверждённые постоянные mediaRefs передаются в инструмент создания контента.

В браузерном ИИ доступ к вложению зависит от возможностей хоста. Если он не предоставляет ссылку или загрузку, загрузите файлы в вебе/Mini App, затем продолжите с агентом. Он не должен обещать доступ, загрузку или выдачу без результата.

Токен собственного Telegram-бота и учётные данные платёжного провайдера можно передать агенту для авторизованного типизированного инструмента выбранного бизнеса. Агент не повторяет секреты в ответах и не помещает их в документы или страницы. Авторизация MCP-коннектора выполняется в настройках приложения.

После короткого отвлекающего вопроса агент возвращается к текущему шагу, а по просьбе остановиться прекращает работу. Завершение подтверждается отдельным действием и состоянием сервера; после него сопровождение настройки выключается.
